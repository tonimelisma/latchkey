# What Latchkey can do, and when

Every use case Claude has on a Mac, tried through the hosted relay by a fresh Claude Code in
each screen state: unlocked, locked (screen on), lid closed while still unlocked (the first minutes), and lid closed and locked.
The display asleep on an unlocked Mac isn't a state of its own: it lasts only the minutes before the
screen lock, and on Toni's Mac it never came up in a day of waiting (dropped by Toni, 2026-11-04).
Generated by `macos/scripts/state-check/state-check.sh report` from a real run; the cases are
in `macos/scripts/state-check/cases.json`. ✅ works, ⛔ refuses and says why, ❌ fails,
↷ not tried because an earlier step failed, — not run in that state yet.

Checked: unlocked: 2026-11-02 22:13:50 (app 0.8.95); locked: 2026-11-03 08:03:04 (app 0.8.100); lid_closed: 2026-11-03 21:08:35 (app 0.8.103); lid_closed_locked: 2026-11-02 13:27:34 (app 0.8.78).

Rows for what was removed on 2026-11-07 (Mail, WhatsApp sending, Notes' window editing, Messages' window actions, Reminders' window setters; Toni: Latchkey never disturbs the user) were taken out by hand; the rest is from the runs above.

## Not offered

- Messages: Delete or react to a message
- Mail: Create, rename, or delete mailboxes; Delete a draft
- Shell: Scripting other apps (osascript) or starting background services (by design)
- Calendar: Invite people or answer invitations (macOS doesn't allow apps to)
- Reminders: Flags, tags, and subtasks (macOS doesn't allow apps to)
