# Regression coverage

Every issue found in Latchkey has a case in a regressions group of
`macos/scripts/state-check/cases.json` and an automated test that fails without its fix and runs
in CI (CLAUDE.md, "Every issue becomes a regression case"). This table names the test for each
case. Mac tests run on GitHub's macOS runner (`mac-build.yml`), relay and Linux tests in `ci.yml`.

Status:
- **covered**: a test already existed that fails if the fix is undone.
- **new**: a test added on 2026-11-24 (pull request #41).
- **partial**: Latchkey's own decision is tested; the rest needs a real third-party site, the
  locked screen, macOS's privacy system, another app's window, or Toni's devices, and is said why.
- **manual**: nothing Latchkey decides can be tested without those.

Surveyed 2026-11-24 (118 cases): 78 covered, 26 new, 12 partial, 2 manual. A new case gets its row here in the same commit as its
fix and test.

Found while writing the tests and fixed in the same pull request: a deleted note read through
Notes' scripting still gave Notes' raw "-1728" error; notes_find with only a bad limit listed
the folders and wasn't an error.
